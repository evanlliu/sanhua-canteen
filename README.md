# sanhua-canteen — 员工食堂预约系统

> 当前版本：**V12（正式定稿）** · 单仓库、双分支、GitHub Pages + GitHub Contents API 直连。以后**只更新根目录 `README.md`**，不再创建 `README_V*.md` 等文件。本文件整合了 V1～V12 的功能和主要更新历史。

## 1. 项目结构与入口

- GitHub 仓库：`evanlliu/sanhua-canteen`
- `main` 分支：员工页 `index.html`、独立后台 `admin.html`、`config.js`、前端 JS/CSS、Token 混淆工具及本说明。
- `data` 分支：`data.json`，包含员工花名册、餐次配置和预约记录。
- 员工页：<https://evanlliu.github.io/sanhua-canteen/>
- 后台页：<https://evanlliu.github.io/sanhua-canteen/admin.html>
- 员工端**不提供后台入口**。静态网页无需 Cloudflare Worker，也不需要第二个仓库。

> **重要安全限制：** 公开仓库里的所有分支都可被读取；前端的 `tokenCiphertext` 与 `keyMaterial` 能一起还原 GitHub 写入 PAT，明文 `adminPassword` 也可被浏览器读取。GitHub Pages 无法提供可靠认证。**当前方案仅建议使用虚构资料作临时测试，不能用来保护真实员工隐私或生产凭据。** 使用真实花名册前请迁移到可安全保管令牌的服务端，并确保历史仓库提交未泄露数据。GitHub Token 的 Contents 写权限覆盖整个选定仓库，并非仅 `data` 分支。

## 2. 员工预约功能（V12 当前规则）

### 员工查找：工号或姓名均可模糊查询

在“**员工工号或姓名**”输入框输入一部分内容，下方自动出现员工下拉结果（工号 + 姓名），点选后会锁定对应的**唯一工号**用于预约，防止重名串号。

- 支持 `8`、`14`、`106`、`008` 等 **1～24 位工号**的完整、前缀、包含搜索；工号 `8` 和 `008` 保持区分。
- 支持中文姓名片段（如 `小明`）、西语/英语姓名片段（如 `CEPEDA`、`ORLANDO`）和多词查询（如 `CEPEDA ORLANDO`）；忽略英文字母大小写和常见拉丁重音符号。
- 工号精确匹配优先，其次工号前缀/包含，然后姓名精确/前缀/包含；最多展示 12 条。输入姓名时也显示工号，请核对后点选。
- “查看我的预约”区域为了准确识别仍然需要**完整数字工号**，不能只输入姓名。
- 手机端预约查询的工号输入框与上方员工搜索框使用一致的 **49px 高度、边框、圆角及内边距**，避免窄屏 Flex 布局压缩输入框。

### 餐次展示与预约时段（V11）

管理后台“餐次与时间设置”中的 **「对员工开放此餐次」** 是员工端**是否显示卡片**的唯一开关：

| 后台开关 | 当前食堂当地时间 | 员工端 | 能否预约 |
| --- | --- | --- | --- |
| 关闭 | 任意 | 不显示此餐次 | 否 |
| 开启 | 开始前 | 显示「尚未开始」，按钮「未到预约时间」置灰 | 否 |
| 开启 | 开始时间（含）至结束时间（不含） | 显示「开放预约」，绿色「立即预约」 | 是 |
| 开启 | 结束时间（含）之后 | 显示「今日已结束」，按钮置灰 | 否 |

示例：后台勾选“午餐 11:30–14:00”和“点心 17:30–20:00”，早上 `08:00` 两张卡片**都显示但都无法预约**；`11:30` 午餐开放，点心仍置灰；`14:00` 午餐结束仍显示；`17:30` 点心开放。后台关闭的餐次完全不出现。

> 此开关**不是**“预约开始时间”的单独配置；预约开放期严格采用后台餐次的开始～结束时间。目前没有“提前一天预约”或“开餐前提前预约”功能。

### 其他预约规则

- “用餐时间（当天）”只读展示 `yyyy-MM-dd HH:mm`，按后台配置的 IANA 时区（初始为 `America/Monterrey`）计算，约每 10 秒同步分钟和餐次状态。
- 只能预约食堂当地**当天**的餐次，不能编辑日期；提交时 GitHub API 再次确认是否在餐次时间内。
- 同一员工、同一天、同一餐次只能预约一次；**相互重叠时间段的不同餐次也不能重复预约**。不同不重叠时段可以分别预约。
- 成功时生成预约号码（例：`CEBA40FD604-D`），可在下方凭**完整工号**查询历史记录。
- 员工首页没有大横幅/品牌页眉，右上角两个悬浮图标分别为三语言选择与“我的预约”跳转；进入页面自动聚焦员工搜索输入框。
- 首次打开页面默认跟随设备语言偏好，支持中文、English、Español (México) 手动切换。

## 3. 管理后台

`admin.html` 与员工端独立。当前后台功能：

- 管理员密码在 `config.js` 的 `adminPassword` 中配置，初始示例为 `1123`；打开登录页后自动聚焦密码框。
- 登录成功后 Cookie 保存**最多 5 小时**的前端登录状态，刷新不续期；退出登录清除 Cookie，过期后需要重新输入密码。
- 查看全量/今日预约统计、员工数量与启用餐次数量；可筛选工号/姓名/预约号、餐次和日期，删除预约并导出筛选结果 CSV。
- 从 `.xlsx` / `.xls` / CSV 导入员工花名册，表头应有 **工号** 与 **姓名**，支持合并更新、全量覆盖；重复工号不能共存。导入花名册不会自动删除预约历史。Excel 应把带前导零的工号列存为文本。
- 自定义最多 12 个餐次的 ID、中文/英文/西班牙语名称、起止时间、排序与“对员工开放此餐次”开关；可新增、编辑、停用或删除餐次。
- **从下拉框选择食堂时区**（默认 `America/Monterrey`），优先提供墨西哥常用时区，并支持其他浏览器内置 IANA 时区；不需要手动键入。切换时区并保存后，员工端的当天时间和餐次开放时段会按新时区计算。

管理后台口令是**前端显示门槛**，不是可靠的服务端权限验证。请勿将之用于生产系统的管理员鉴权。

## 4. 配置与部署

### `main/config.js`

只需要一个仓库 `sanhua-canteen`，`config.js` 在 `main` 分支根目录：

```js
window.APP_CONFIG = {
  github: {
    owner: 'evanlliu',
    repo: 'sanhua-canteen',
    branch: 'data',
    path: 'data.json',
    adminPassword: '1123',
    tokenCiphertext: '', // 本地 token-tool.html 生成
    keyMaterial: '',     // 本地 token-tool.html 生成
  }
};
```

不要把明文 PAT 发给其他人，不要把真实 PAT 放入公开仓库。`token-tool.html` 的混淆**不等于加密保密**：密文和密钥同时公开时任何访客均可能恢复 PAT。若仅本地测试，建议选用只限该仓库、短有效期、可随时撤销的测试凭据。**更新包中的 `config.js` 是空凭据模板，不要覆盖你现有的配置文件。**

### 发布到 GitHub Pages

1. 将网页文件上传至 `main` 分支根目录；`index.html` 需位于根目录。
2. 在同一仓库建立 `data` 分支，于根目录放置 `data.json`（已有分支和记录则保持不动）。
3. 在仓库 `Settings → Pages` 使用 `Deploy from a branch → main → /(root)`。
4. 发布后在浏览器使用 `Ctrl + F5` 强制刷新，或用隐身模式验证更新。
5. 演示访问可在员工端网址追加 `?demo=1`；演示模式仅使用本地浏览器数据，不会写入 GitHub。

**V11 已有仓库的最小更新：** 仅向 `main` 分支根目录替换 `styles.css`、`admin.html`、`admin.js` 和 `README.md`（共 4 个文件）。`config.js`、员工预约业务 JS 及 `data` 分支均无需修改。保存时区设置后，员工端刷新即可应用新的时区。

## V12 — Plant 选择、完整花名册导入及预约号后缀

- 员工预约需选择 **Plant D / G / B / H** 中的一个；Plant 由员工手动选择，不依据部门字段自动推测。
- 预约提交、确认弹窗、预约结果、后台记录和 CSV 导出中都包含 Plant；旧预约记录仍可查询和删除。
- **预约号码正式规则（已确认）**：`C` + **10 位大写十六进制随机字符** + `-` + **一个 Plant 字母**（仅 `D` / `G` / `B` / `H`），例如 **`CEBA40FD604-D`**。编号由系统生成，员工不能手动编辑。
- 示例后缀：`CEBA40FD604-D`（Plant D）、`CEBA40FD604-G`（Plant G）、`CEBA40FD604-B`（Plant B）、`CEBA40FD604-H`（Plant H）。这些共享同一随机主体的编号仅用于格式演示，实际每笔新预约使用独立随机主体。
- **兼容历史预约**：之前不带 Plant 后缀的编号（如 `CEBA40FD604`）继续支持查询和后台删除；新的预约必须带有效 Plant 后缀。Plant 是预约时员工选择的地点，与花名册中的部门、工厂或员工类型没有自动绑定关系。
- 后台新花名册导入时完整保留 **全部原始列名及对应列值**：`data.rosterColumns` 保存列名列表，`data.employees[].values` 保存按列顺序排列的完整信息，`employeeId` / `name` 仍供预约搜索。这样既保留 19 列，又避免在每名员工的数据中重复存储长字段名。
- 花名册后台增加“查看”完整信息和“导出完整花名册 CSV”。原有预约记录不会因全量覆盖员工名单而清除。
- 新版示例 Excel 共有 19 列、1441 人，其中 `ID` 与 `Name `（表头带一个末尾空格）分别映射到工号/姓名；所有其他列同样保留。Excel 的 `Hiring Date` 日期序列号会按 Excel 日期基准转为 ISO 日期（`yyyy-MM-dd`）方便查看。若合并更新的 Excel 表头与上次不同，请使用全量覆盖，避免列数据错位。
- 接口为避免 GitHub Contents API 读取超过 1MB 的文件，超过 800KB 会改为紧凑 JSON 序列化；超过 900KB 会提示备份归档。不包含真实员工花名册的任何内容，只有后台导入后才会保存到数据分支。
- **特别提醒：** 公开 GitHub 仓库的 `data` 分支可以被互联网用户读取。包含完整员工人事资料（尤其是成本中心、职位、部门）的花名册不应放入公开仓库。Token 混淆、前端登录密码及隐藏页面都不能提供可靠保密。
