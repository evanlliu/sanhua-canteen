# sanhua-canteen V9 — 预约时段严格校验 / 当前时间显示

本次以 V8 的完整 main 分支包为基础修改，仅涉及 6 个文件；`config.js`、管理后台、`data` 分支均无需改动。

## 修复说明

- 之前只检查 `当前时间 < 结束时间`，会把未来才开始的餐次误判为“开放预约”。
- 现在要求餐次已启用，预约日期是食堂当地当天，且 `开始时间 <= 当前时间 < 结束时间`。
- 页面只显示此刻可预约的餐次；未开始、已结束和未启用的餐次均隐藏。
- 点击预约时、演示模式提交时、GitHub API 正式写入前再次检查时段。超过边界会拒绝提交，避免只通过改网页请求提前预约。
- `用餐日期（当天）` 改为 `用餐时间（当天）`，只读显示 `yyyy-MM-dd HH:mm`。时间由后台配置的 IANA 时区（默认 `America/Monterrey`）计算，页面每 10 秒同步分钟显示和可预约餐次。提交记录仍采用 `yyyy-MM-dd` 日期，不改变现有 `data.json` 结构。
- 中文、英文、墨西哥西班牙语均已同步翻译。

## 部署

将最小更新包中的以下文件放进 `evanlliu/sanhua-canteen` 仓库的 `main` 分支**根目录**，覆盖对应文件：

1. `index.html`
2. `staff.js`
3. `i18n.js`
4. `client-api.js`
5. `github-store.js`
6. `meal-schema.js`

不要替换现有的 `config.js`，不要修改 `data` 分支。等待 GitHub Pages 发布完成后，以 `Ctrl + F5` 强制刷新。后台的餐次配置时间决定预约开放时间，如需提前预约必须另行设计独立的“预约开放窗口”，不能将用餐时间和预约开始时间混淆。

## 验证

`node tests/time-window.test.mjs`：22 项模拟接口和规则测试通过；所有主要 JS 文件通过 Node 语法检查。

本环境的浏览器导航被安全策略阻止，因此本次没有进行真实 GitHub Pages 在线端到端测试。上线后请用已开放的餐次核对一次显示和提交行为。

## 关于安全性

此项目按现有临时 GitHub Pages 直连方案运行：前端混淆 Token 和明文配置的后台密码无法提供真正的安全防护。请勿在公开仓库存储真实敏感花名册或长期有效的写入凭据。
